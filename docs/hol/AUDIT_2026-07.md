# July 2026 Audit — Pain Points and Design Findings

This document records a hands-on audit of the `hol` branch performed on
2026-07-14: fresh student-style proving at the current frontier, an
adversarial diagnostics review, a grading/automation surface review, and a
design-documentation cross-check. Every finding below was reproduced against
`target/debug/cetacea_cli` from a green 92-file corpus baseline. Items already
recorded in [`../book/FRICTION.md`](../book/FRICTION.md) (1–35) are not
repeated. Tool-facing findings are also entered in the friction ledger as
items 36+; this document is the full record with reproductions.

Severity is from the teaching perspective: does it let a student pass without
the mathematics, fail a student who did the mathematics, or block a proof the
course needs?

**Disposition (same day).** A1, A2, B2, B3, and C1 were fixed on
2026-07-14, together with the D-section documentation drift and the missing
CI shadow-gate step; the corresponding entries below carry a RESOLVED
marker describing the fix, and friction ledger items 36–45 record the
permanent history. C2–C10 were fixed on 2026-09-03. A3/A4, B1, B4, and B5
remain open.

## A. Grading integrity

### A1. Predicate-redefinition bypass earns full credit (HIGH — RESOLVED 2026-07-14)

Fixed by canonical signatures (positional binders, package-qualified
references) plus the `required_imports` manifest lower bound; the shipped
manifests were regenerated and
`assignment_manifest_rejects_predicate_redefinition_bypass` pins the
regression. Original finding:

A submission that never imports the graded package can satisfy an assignment
manifest by rebuilding the required statement's *spelling*:

```text
namespace F
data List
| nil
| cons(Traffic, List)
def HasCard (xs : List) (n : Nat) : Prop := True
end

theorem traffic_has_card_three :
  F.HasCard(F.cons(red, F.cons(yellow, F.cons(green, F.nil))), 3) := by
  trivial
```

Against the shipped `docs/hol/pilot/finite_traffic.ctea-assignment` this
exits 0 with no violations. Three root causes compound:

1. `required_theorem` signatures are compared as canonical *surface text*,
   so a source-local `F.HasCard` matches the intended package `HasCard`;
2. `allowed_imports` is an upper bound only — importing nothing violates
   nothing;
3. package aliases and `namespace` blocks share a namespace, but nothing
   requires the alias in the manifest text to refer to a package.

Exact-name shadowing after a real import *is* rejected
(`cannot redeclare `F.HasCard``), so the attack works precisely when the
required package is not imported under the alias the manifest text uses.
The durable fix is to compare required theorems by resolved declaration
identity (package-qualified receipts already exist per
[`H6_SURFACE_IMPORTS.md`](H6_SURFACE_IMPORTS.md)), which also fixes A2.

### A2. Frozen signatures are alias- and alpha-sensitive (MEDIUM-HIGH — RESOLVED 2026-07-14)

Fixed by the same canonical-signature change; alias and bound-variable
renamings no longer affect grading. Original finding:

Changing `import std/hol/finite@1 as F` to `as G` in the chapter 13 solution
fails all five required theorems with `signature does not match manifest`;
renaming a theorem's `(P : Prop)` parameter to `Q` fails the same way; an
instructor hand-typing `P \/ not P` where the canonical print is
`P \/ (not P)` silently fails every correct student. This contradicts the
plan's claim that signature freezing compares "canonical core statements, not
source formatting", and it grades exactly the things a proof course teaches
students do not matter. There is no manifest generator; the only safe
authoring path (copy `hol_shadow.theorems[].signature` from `--json` output)
is undocumented.

### A3. One sanctioned HOL theorem opens the whole `hol` profile (MEDIUM)

`ch15-solutions.ctea-assignment` must declare `profile = "hol"` only because
pigeonhole transitively uses `map`. Under that manifest a student may use any
higher-order machinery. A per-theorem grant (`allowed_theorems`, mirroring
`allowed_axioms`) would keep pigeonhole assignments enforceably
`fol+induction` outside the sanctioned lemma. Without it, the student-visible
lesson is "pigeonhole requires HOL" — a library artifact, not mathematics.

### A4. Autograder JSON and robustness gaps (MEDIUM)

- A theorem that *fails* does not appear in `--json` `theorems[]` at all;
  failure is only recoverable from prose in `diagnostics[]`. Renamed,
  failed, and never-written are indistinguishable to a tool.
- ~1,000 nested parentheses abort with a stack overflow (exit 134) and empty
  JSON on stdout; ~50,000 hang past 30 s. Exit codes stay nonzero, but batch
  graders need per-file resource limits.
- The exit-code contract itself audited clean: 0 accept / 1 source-or-policy
  / 2 missing-or-malformed manifest, across parse errors, failed proofs,
  policy violations, missing files, and mistyped flags. Rename detection,
  per-theorem incompleteness reports, unused-axiom rejection, homoglyph
  rejection, and solution-import blocking all held under adversarial probes.

## B. Walls in the mathematical surface

### B1. No user recursion over the imported generic `List` (HIGH)

`defrec sum_list (l : C.List Nat) : Nat` is rejected: recursion is allowed
only over `Nat` and locally declared `data` types. No package exports
fold/sum. Degree sums and edge counts — the roadmap's own handshake vertical —
are inexpressible against the counting library today. The workaround
(a private monomorphic list datatype) abandons every package theorem.

### B2. False closed `Nat` equalities are effectively unrefutable (HIGH — RESOLVED 2026-07-14)

Fixed: built-in Nat now gets datatype-style no-confusion in both engines
(`contradiction` and `simp` refute `1 = 2` and `succ(n) = 0`; open
`succ`-lifted equalities deliberately stay visible so the ch09 mistake
fixtures still reject). Original finding:

`contradiction` refutes `red = yellow` (datatype no-confusion) but not
`1 = 2`; `simp` computes closed `le(2, 1)` to `False` but leaves closed
`1 = 2` untouched; `std/nat.ctea` has `succ_inj` but no `succ_ne_zero`. The
only discovered route is an expert detour:

```text
have le21 : le(2, 1) := by
  rewrite <- h
  exact le_refl {n := 1}
simp at le21
exact le21
```

Consequence: `Nodup` for any concrete numeric enumeration is expert-only —
a full `HasSize({1, 2}, [1, 2], 2)` proof measured 78 lines. This is a
*possibility* gap on top of the known ceremony gap (friction 24): closed
constructor/numeral disequality should compute under `simp`/`contradiction`.

### B3. Chapter theorems do not graduate into libraries (MEDIUM — RESOLVED 2026-07-14)

Fixed: `std/nat.ctea` gained `succ_not_le_self`; `std/hol/counting.ctea`
gained the append-coverage, disjoint-append, exact disjoint-union, and
union upper-bound theorems; the new `std/hol/pigeonhole.ctea` exports the
pigeonhole surface. Original finding:

`ex15_5` (`le(succ(n), n) -> False`), `ex15_6` (pigeonhole), `ex16_2`
(disjoint append preserves `Nodup`), and `ex16_3` (exact disjoint-union size)
exist only in solutions files. A three-way disjoint-union theorem composes
cleanly on top of `ex16_3` — but only by importing
`docs/book/hol-code/ch16-solutions.ctea`, which no student can honestly do.
Friction 30's "the counting core is reusable" is only half-true until these
graduate to `std/nat.ctea` / `std/hol/counting.ctea` / a pigeonhole module.

### B4. One package under two aliases yields non-unifiable types (MEDIUM)

`C.List Nat` (via `counting.ctea`) and `F.List Nat` (via `list@1`) are the
same package datatype but do not unify; meanwhile two *different* packages
merge under one alias (chapter 15 imports `finite@1` and `cardinality@1`
both as `F`). Mixing chapter 13–15 style with chapter 16 style produces
opaque type errors that never mention the shared identity, and theorem search
lists the same theorem once per alias route.

### B5. Import ergonomics (MEDIUM)

- Two innocent unaliased imports (`std/prelude.ctea` + `std/hol/counting.ctea`)
  produce an error cascade blamed *inside the standard library*
  (`std/hol/counting.ctea:16: unknown predicate `Nodup``) after a one-line
  alias-collision root cause; a student reads it as "the library is broken".
- Import resolution is cwd-dependent: a homework file checks from the
  repository root and fails from its own directory with no search-path hint.
  The browser embeds `std/` as virtual files; the native CLI could do the
  same or honor an environment variable.
- After a failed import, follow-on diagnostics misdescribe unknown theorem
  references (`named arguments like `{P := ...}` can only be used with
  theorem or axiom names`).

## C. Diagnostics (adversarial review)

**Disposition (2026-09-03).** C2–C10 were fixed as one batch with a
regression test per item (`diagnostics_batch_tests` in `lib.rs`; search in
the CLI tests); friction ledger item 45 records the details.

Ranked; each reproduced. The strongest existing patterns — parameter lists
("available parameters: `A`, `P`, `Q`"), the constructive `by_cases`
explanation, countermodel notes ("false when m = 1, n = 0. No proof can
close it") — are worth propagating into the gaps below.

1. **One-line `by` silently discards its tactic** (RESOLVED 2026-07-14:
   trailing text after `:= by` now parses as the first tactic line, and
   glued forms like `bytrivial` are rejected at parse time).
   `theorem t : True := by trivial` dropped `trivial` and reported
   `unsolved goal `True``.
2. **Bare `cases h` → "unknown tactic `cases h`"** while the help text lists
   `cases` as a valid tactic; it needs the `with`-arm skeleton instead.
3. **Unknown package version falls through to the filesystem**:
   `import std/hol/list@2` → `No such file or directory (os error 2)`;
   the registry knows the three real packages and should name them.
4. **No "did you mean" anywhere**; typo'd theorem references are reported as
   `unknown hypothesis` and steered toward `.left`/`.right` projections.
5. **A declared predicate passed as a function argument is called
   "unknown function"** (`H.map(Even, xs)`) — the real lesson (data-valued
   function vs `Prop`) is the fragment boundary chapters 14–16 teach.
6. **The `refl` failure help suggests `simp` on package-function goals**
   (`F.length(F.cons(...)) = 1`) where `simp` provably does nothing; the
   help should name the package computation theorems instead.
7. **`defrec` arms reject term syntax** — `| node(l, v, r) recl recr =>`
   fails with "cases must follow the constructor declaration order" (order is
   not the problem; arms want space-separated binders, terms want parens).
8. **Misindented case-arm bodies** surface as `expected `right` case arm` at
   the student's own tactic line, with no mention of the indentation rule.
9. **Aliased imports give no hint for bare names** (`add_comm` after
   `import std/nat.ctea as nat` should suggest `nat.add_comm`), and
   redeclaration errors never cite the import that owns the first
   declaration.
10. **Multi-word theorem search matches nothing** (`search add succ` — terms
    should be AND-ed; students think in words, not underscore-joined names).

## D. Architecture and process drift (docs corrected and CI step added 2026-07-14; the underlying H1 extraction itself remains open)

- **Phase H1 was skipped silently**: every phase in
  [`../HOL_REARCHITECTURE_PLAN.md`](../HOL_REARCHITECTURE_PLAN.md) has a
  Status paragraph except H1; the module split never happened;
  `scripts/check_kernel_boundary.py` guards the 41-line `kernel.rs` facade
  plus six `hol/` modules while the legacy kernel — the sole authority for
  every package-free student file — lives unguarded inside the 27k-line
  `lib.rs`. The "small auditable kernel, CI-enforced boundary" story is
  currently true only of the shadow engine.
- **The 600-statement shadow gate is not in CI** (`ci.yml` runs tests,
  corpus, `hol_baseline.py check`, and the boundary script only; no
  `hol_shadow.py check`, no feature-disabled build, no release/Wasm build).
- **`allow_extensionality` / `allow_choice` are inert**: no non-test code
  path can emit those proof features; their adversarial evidence is
  fabricated receipts. Fail-closed, but the manifest docs oversell them.
- **`BASELINE.md` mixes three measurement eras** without labels, and
  `DISCRETE_MATH_GAP_AUDIT.md` still claims signature freezing "remains
  outstanding".
- **The H3 "trusted core auditable" gate metric was dropped**: a conditional
  pass at ~3,713 pre-test lines, now ~5,484 (+48%) with byte sizes but never
  line counts re-measured.

## E. What held up well

Dual-certified checking latency is a non-issue (0.2–0.7 s on
package-importing files). The exact-baseline bookkeeping reproduces to the
byte. Countermodel notes are exactly the right pedagogy for truncated
subtraction. The three-way disjoint union composes cleanly over `ex16_3`,
and the roadmap's tree vertical already works: `vertices(t) = succ(edges(t))`
proves in nine lines with one library lemma.
