# Friction Log — What the Book Exposed About Cetacea

Writing chapters 5–12 (with every proof machine-checked) surfaced the
places where Cetacea could not yet express the pedagogically natural
thing. This is the tool-improvement ledger generated by the book,
roughly ordered by how much a fix would improve the teaching
experience. Resolved entries remain here so the roadmap's item numbers
stay meaningful.

## High impact

1. **Resolved: defs can pass predicate parameters to other defs.**
   `def Equivalence (R) := Reflexive(R) /\ Symmetric(R) /\ Transitive(R)`
   and `def Bijective (G) := Injective(G) /\ Surjective(G)` both check.
   Chapters 7 and 8 now use those names directly.

2. **Resolved: a `def`-defined relation is usable as a predicate argument.**
   `def SameMood (x y : Person) : Prop := ...` then `Reflexive(SameMood)`
   now checks. Chapter 7 exercises use the natural "name the relation,
   then classify it" flow.

3. **Resolved: mixed-type predicate lambdas.** A graph for
   `age : Person -> Nat` can be written as
   `fun (x : Person) (n : Nat) => age(x) = n`, while the old
   `fun x y : T => ...` shorthand still works when all binders share a
   type.

4. **Resolved: post-`apply` goals stay usable with folded library lemmas.**
   `apply subset_antisymm` can now be followed by
   `exact subset_union_left {...}` against the folded subset subgoal, and
   `apply modeq_zero_to_divides` works directly against a folded
   `Divides(5, 20)` goal. Matching tries folded formulas first and then
   falls back to def-normalized formulas, so `exact` also works when one
   side is folded and the other is unfolded.

5. **Resolved: composition theorems are usable at concrete graphs.**
   `exact compose_injective {F := fun x y : Nat => succ(x) = y; ...}`
   now checks, and Chapter 8 includes the "succ ∘ succ is injective"
   payoff against the library theorem.

6. **Resolved: countermodel notes cover small Nat arithmetic and
   bounded first-order worlds.** False pure `Nat` arithmetic goals with
   free variables report assignments such as `n = 0`, both for theorem
   statements and open goals. Relation-heavy statements over abstract
   sorts, declared predicates, and equality now get the same signal via
   a finite-domain search over worlds of size 1-3. The search is
   intentionally bounded, and still bails silently on sets, functions,
   and richer terms.

## Medium impact

7. **Resolved: `have` with a stated formula drives parameter inference.**
   `have hle : le(2, 2) := le_refl` now uses the annotation to infer
   `le_refl`'s theorem parameter, matching the way `exact le_refl`
   works against the same goal.

8. **Resolved: theorem references accept positional term arguments.**
   `exact modeq_refl m x` and `exact modeq_sym m x y h` now work. Term
   arguments fill theorem parameters left-to-right before ordinary
   forall or implication arguments are processed.

9. **Resolved: explicit-instantiation name capture.** Explicit theorem
   arguments that fix a schema parameter no longer reopen that parameter
   during premise matching. The colliding
   `congr_pred {...; x := succ(x); ...}` probe now checks, while the
   adversarial wrong-premise variant still fails with an accurate type
   mismatch.

10. **Resolved: no-op `simp` warns instead of failing.** Defensive
    `simp`s no longer break when an earlier step already normalized the
    goal. They leave the proof state unchanged and report a warning note
    such as "this `simp` did nothing; consider deleting it".

11. **Resolved: rewrite directions are explicit in docs and book
    style.** `rewrite <- h` and bare `rewrite h` are documented as the
    same right-to-left direction, while `rewrite -> h` is left-to-right.
    Chapter 5 now warns Lean/Rocq readers directly, and normal book
    examples use explicit arrows.

12. **Resolved: `strong_induction` failures teach the explicit
    predicate fix.** A bare `apply strong_induction` now carries a
    "Provide the predicate parameter" help entry with a `try:` block
    like `apply strong_induction {P := fun m : Nat => ...}`.

13. **Resolved: `induction` dependency refusals suggest the standard
    fix.** ``cannot induct on `n` while hypothesis `h` depends on it``
    now explains that the hypothesis should be introduced inside the
    induction arms and shows the corresponding tactic skeleton.

## Lower impact / polish

14. **Resolved: closed successor numerals print as decimals.** Error
    messages now display closed `succ` towers as numerals (`5` instead
    of `succ(succ(succ(succ(succ(0)))))`), while mixed terms such as
    `succ(n)` remain symbolic.

15. **Resolved: computation has an explicit goal preview.** Specialized
    applications retain their written premises: `apply h 0 1` leaves
    `le(0, 1)`, with a separate `Computes to: True` preview. Browser and
    terminal goal displays expose definitional computation without replacing
    the written goal, and browser explanations show the same preview before
    and after steps. Computation to `False` remains a proof obligation.

16. **Resolved: axioms print as trusted.** Accepted axioms now display
    `trusted axiom foo`, keeping proof-mode labels for proved
    theorems and using theorem dependency output for later axiom use.

17. **Resolved: ambiguous one-occurrence rewrites report the selected
    occurrence.** When a non-`all` `rewrite` has several candidates,
    Cetacea accepts the proof but emits a warning note such as
    ``rewrote the 1st occurrence of `mother(alice)` ``. That keeps
    wrong-direction rewrites and accidental literal rewrites localized
    to the tactic line; `rewrite all` remains available when every
    occurrence should change.

18. **Resolved: the classroom sources use qualified library names.** Book,
    course, and tutorial sources import `std/qualified_prelude.ctea`; library
    calls use names such as `nat.add_comm`, `list.length_append`, and
    `fun.Total`. Student declarations can use `add_comm` and `length_append`
    without collision suffixes. Qualified prefixes that are also keywords,
    such as `fun.Total`, coexist with lambda syntax. The legacy prelude remains
    available for compatibility. The migration preserves 398 root receipts;
    see [CLASSROOM_NAMESPACE_MIGRATION.md](../CLASSROOM_NAMESPACE_MIGRATION.md).

## Surfaced writing the advanced FOL examples

Writing `examples/fol_advanced.ctea` (quantifier distribution laws, the
drinker's and barber paradoxes, relation classification, exists-unique,
and the quantifier De Morgan biconditionals) exercised the first-order
layer harder than the book chapters did. It held up well — all fifteen
theorems check — but three things stood out.

19. **Resolved: structural tactics auto-unfold a folded definitional
    goal.** A goal like `Symmetric(R)` is a `def` applied to arguments,
    so `intro`/`split` could not see the `forall`/`->` inside it and
    failed with "intro expects an implication or universal goal" — the
    most common first-try failure across the relation theorems. Now
    `intro`, `split`, `left`, `right`, and `exists` weak-head-normalize
    the goal's definitional head on failure and retry, wrapping the proof
    in a kernel-checked `Convert` node. Nested definitions are peeled as
    far as needed (`split` reaches through `Bijective` to
    `Injective /\ Surjective`). `examples/fol_advanced.ctea` now proves
    `Reflexive`/`Symmetric`/`Transitive`/`Euclidean` goals with no
    explicit `unfold`.

20. **Resolved: `have h : P := by ...` now runs an inline tactic block.**
    A stated `have` used to accept only a subgoal (`have h : P`,
    discharged by the following indented tactics) or a single proof
    expression (`have h : P := h.left`); the `:= by` block form failed
    with the baffling `unknown hypothesis \`by\``. It now parses the
    indented block, proves the stated formula with it via the same
    machinery as `cases`/`induction` arms, and continues. Blocks nest
    (a `have := by` can contain `cases` or another `have := by`). The
    barber proof in `examples/fol_advanced.ctea` uses the block form for
    its `not Shaves(b, b)` lemma.

21. **Works well: countermodels catch invalid quantifier statements.**
    The invalid converse of the quantifier swap,
    `(forall y, exists x, R(x, y)) -> exists x, forall y, R(x, y)`,
    reports "false in a 2-element domain where R = {(a,b), (b,a)}". The
    finite-world search is exactly the right pedagogical tool for the
    "order of quantifiers matters" lesson.

22. **Resolved: `inl`/`inr` are accepted as disjunction arm aliases.**
    `cases h with | inl hp => ... | inr hq => ...` now checks, alongside
    the native `| left ... => | right ... =>`, so Lean/Rocq muscle memory
    no longer trips on `expected \`left\` case arm`.

## Surfaced writing the finite-mathematics extension

Chapters 13–14 are the first book chapters written directly against the
versioned HOL package surface. They confirm that restricted FOL profiles and
HOL can coexist in one course, but they also found the following concrete
edges.

23. **Resolved: structural definitions can fill function-valued package
    parameters.** A checked `defrec encode : Coin -> Bit` could be called and
    its inverse could be proved, but `map(encode, xs)` was rejected as
    “unknown function `encode`.” The only source workaround was an
    uninterpreted `func` plus trusted computation axioms. Monomorphic
    structural definitions now expose their checked arrow signature to
    rank-one function-argument validation and lower to their existing HOL
    definition. Chapter 14's concrete transport theorem is the regression
    case; the inverse proofs stay `fol+induction` and the mapped theorem is
    honestly `hol`.

24. **Resolved: routine finite enumeration has a checked derivation tactic.**
    `finite` constructs proofs of concrete constructor-list `HasCard`, `Nodup`,
    length, membership, and coverage claims. Chapter 13's named three-colour
    enumeration now has a one-tactic proof, with a trust-free constructive
    `fol+induction` receipt. The explicit component proofs remain as exercises.
    Regression tests reject duplicates, omitted constructors, wrong lengths,
    infinite-type coverage, and spoofed helper names. Coverage currently supports
    datatypes with nullary constructors; general proposition-aware `simp` remains
    outside this tactic's scope.

25. **Resolved: package theorem parameters are inferred from rewrite/apply
    goals.** `rewrite -> F.length_cons` infers the type, head, and tail from
    the selected occurrence. Projected `apply F.member_cons.right` and
    `apply F.nodup_cons.right` infer from the goal; function parameters in
    cardinality lemmas are inferred from named functions. Explicit arguments
    remain constraints, and parameters absent from the selected conclusion or
    rewrite side still require input. Chapter 13 examples and solutions now
    use this inference, with unchanged checked receipts.

26. **Resolved: term abbreviations work through unfolding and rewriting.**
    `unfold name` now expands a named term inside the goal, including beneath
    quantifiers, and `simp [name]` accepts transparent definition names.
    `docs/hol/examples/term_abbreviations.ctea` checks parameterized terms,
    membership, imported abbreviations, and rewriting through both kernels.
    Single rewrites expose terms when direct matching fails; `rewrite all`
    exposes terms before matching in goals and named hypotheses. Binder-capture
    negatives and saved-hypothesis evidence are regression-tested.

27. **Resolved: direct induction now recognizes imported polymorphic
    datatypes.** `induction xs` rejected `xs : F.List A` even though the List
    package exported a checked induction theorem. The workaround required an
    explicit predicate-valued `apply F.list_induction`. Logical imports now
    register their rank-one datatype/constructor metadata, and the induction
    tactic elaborates the ordinary `nil`/`cons` arms through that checked
    theorem. The receipt retains the package dependency and the least
    `fol+induction` fragment. Dependent-hypothesis diagnostics also render the
    List constructor skeleton rather than the old hard-coded Nat skeleton.

28. **Resolved: generic `map` exposes checked constructor equations.** The
    cardinality package had `map_length` and membership transport but no public
    way to reduce `map(f, nil)` or `map(f, cons(h,t))`. Consequently even the
    base case of “mapped membership has a source witness” was inaccessible
    from source. `map_nil` and `map_cons` are now checked theorem schemas backed
    by the existing structural definition, registered transactionally and
    available through native/browser imports. They add no reduction axiom.

29. **Resolved: an internal recursion closure no longer mislabels open order
    formulas as HOL.** The checked binary `le` definition uses the inaccessible
    predicate-valued helper `@compat.le_tail`. Delta-normalizing
    `not le(succ(n), n)` exposed that helper and classified an ordinary order
    statement as `hol`. Fragment metadata now marks only this internal helper
    as first-order implementation scaffolding. Saturated open order remains
    `fol+induction`; public structural functions such as `map` still expose
    genuine function-valued arguments as HOL.

30. **Resolved at the checked source-module layer: the counting core is
    reusable.** Chapter 15's proof-relevant member removal and duplicate-free
    inclusion bound now live in `std/hol/counting.ctea`, together with
    `member_append` and a set-relative `HasSize` interface. Chapter 16 proves
    finite-union cardinality by applying the inclusion theorem rather than
    copying its removal induction. The source remains visible while the
    decidable-overlap API is unsettled; freezing a builtin package ID is a
    separate publication step, not a prerequisite for checked reuse.

31. **Resolved 2026-09-04: local rewriting and term generalization.**
    `rewrite -> e at h`, `rewrite <- e at h`, and `rewrite all -> e at h`
    preserve checked evidence for a replacement hypothesis without changing
    the target. `revert ys` now generalizes a term variable and its dependent
    hypotheses before induction. The counting inclusion proof is tested with
    `ys` as an ordinary theorem parameter, reverted inside the proof; students
    no longer need to choose the universal quantifier's placement in advance.
    Independent facts remain available. Dependency tracking includes rewritten
    formulas and their evidence, and HOL regressions prevent variable capture.

32. **Resolved with an explicit classical witness API.** The base pigeonhole
    theorem remains constructive. `std/hol/pigeonhole_classical.ctea` exports
    `pigeonhole_collision`, proving `exists x1 x2, x1 != x2 /\ f(x1) = f(x2)`.
    The checked receipt records classical reasoning and its HOL dependency,
    with no axioms or holes. A companion example also exhibits a concrete pair
    constructively. Assignment grants do not waive the classical restriction.
    Computing a pair for an arbitrary finite function would require a separate
    decidable/search interface; the generic API establishes existence.

33. **Resolved: subset cardinality is no longer forced through whole-type
    `HasCard`.** `HasCard(xs,n)` says every value of the carrier type occurs in
    `xs`, so it cannot distinguish two subsets `S` and `T` of the same type.
    Chapter 16's transparent `HasSize(S,xs,n)` records `Nodup`, length, and an
    exact `Member(x,xs) <-> x in S` correspondence. Disjoint union constructs
    a new witness by append; arbitrary union consumes a supplied witness and
    proves the expected upper bound. All of this remains `fol+induction`.

34. **Open, medium impact: checked source libraries have no direct publication
    path to a versioned logical package.** A `.ctea` module is dual-checked and
    reusable, but the current `std/hol/name@1` registry requires each theorem
    to be reconstructed manually as de Bruijn-indexed Rust proof terms. There
    is no package compiler that takes already checked source declarations,
    assigns stable receipt names, and emits a transactional registry record.
    Counting should not be duplicated in Rust merely to obtain an `@1` suffix;
    design that publication boundary after the source API survives another
    consumer.

35. **Resolved 2026-09-04: multiline definitions and projected application.**
    Definition bodies now continue until the next declaration, preserving
    comments and physical error locations. The elaborator advances its
    proposition cursor when processing `.left` or `.right`, so an expression
    such as `(has_size_members ... x).left member_x` applies to the selected
    implication. Native regression tests include the real counting expression,
    folded definitions, both projections, and rejected wrong-premise and
    wrong-target applications. Parser depth, token, size, and biconditional
    expansion limits also reject excessive input before it exhausts resources.

## Surfaced by the July 2026 audit

A hands-on audit (fresh student-style proving, adversarial diagnostics
probes, a grading-surface review, and a design-doc cross-check; full record
in [`../hol/AUDIT_2026-07.md`](../hol/AUDIT_2026-07.md)) added the entries
below. Several were fixed the same day; the fixes are noted inline.

36. **Resolved: assignment manifests compared signatures as surface text,
    so a submission could fake the alias spelling.** A file that never
    imported the graded package could declare `namespace F`, a fake
    `HasCard := True`, and earn full credit from
    `finite_traffic.ctea-assignment` with `trivial`. Required-theorem
    signatures are now canonical: binders print positionally (`?0`, `?1`,
    ...) and package references print as stable package-qualified
    identities (`std/hol/list@1.cons`), so source-local imitations cannot
    match. A `required_imports` manifest key adds the lower bound: the
    graded packages must actually be imported. Shipped manifests were
    regenerated; `--json`'s `hol_shadow.theorems[].signature` remains the
    authoring source of truth.

37. **Resolved: correct submissions failed the signature check for alias
    or parameter renaming.** `import std/hol/finite@1 as G` instead of
    `as F`, or renaming `(P : Prop)` to `(Q : Prop)`, failed every
    required theorem. The canonical form above is alias- and
    alpha-invariant, so those choices no longer affect grading; logically
    equivalent but structurally different restatements still fail by
    design.

38. **Resolved: false closed numeral equalities were effectively
    unrefutable.** `contradiction` closed `red = yellow` via datatype
    no-confusion but not `1 = 2`; `simp` computed closed `le(2, 1)` to
    `False` but left closed `=` untouched; `std/nat.ctea` had `succ_inj`
    but no `succ_ne_zero`. The only route was a five-line rewrite detour
    through `le`. Built-in Nat now gets the same no-confusion treatment as
    declared datatypes in both engines: `zero`/`succ` are disjoint and
    `succ` towers peel when the comparison bottoms out at a decided
    truth value, so `contradiction` and `simp` refute `1 = 2` and
    `succ(n) = 0` directly, dual-checked. Open `succ`-lifted equalities
    are deliberately not identified with their peeled forms, so induction
    exercises still require the explicit lift (the ch09 mistake fixture
    pins this). `refl` on a decided-false numeral equation now reports
    "the sides compute to the different numbers 4 and 5" with an
    "equation is false" help instead of suggesting a useless `simp`.

39. **Resolved: chapter-proven reusable theorems were stranded in
    solutions files.** Pigeonhole (`ex15_6`), `le(succ(n), n) -> False`
    (`ex15_5`), disjoint-append `Nodup` (`ex16_2`), and exact
    disjoint-union size (`ex16_3`) existed only in
    `docs/book/hol-code/*-solutions.ctea`, so composing past a chapter
    meant importing solutions or re-proving. `std/nat.ctea` gained
    `succ_not_le_self`; `std/hol/counting.ctea` gained
    `has_size_union_member_append`, `nodup_append_disjoint`,
    `has_size_union_disjoint`, and `has_size_union_le`; the new
    `std/hol/pigeonhole.ctea` module exports `member_map_preimage`,
    `nodup_map_of_injective`, and `pigeonhole`. A three-way disjoint-union
    theorem now composes from library exports alone.

40. **Resolved: tactics written on the `by` line were silently
    discarded.** `theorem t : True := by trivial` dropped `trivial` and
    reported ``unsolved goal `True` `` — the worst diagnostic failure mode
    found, and the first thing every Lean-trained student types. Trailing
    text after `:= by` is now parsed as the first tactic line (columns
    preserved for error spans), and glued forms like `bytrivial` are
    rejected at parse time instead of parsing as an empty proof.

41. **Resolved 2026-09-03.** `defrec` now recurses over an imported
    package datatype applied to concrete type arguments (`C.List Nat`),
    with bare-leaf or alias-qualified constructor arms, fixed parameters,
    and package-typed results; the definition is certified by the HOL
    kernel as a structural definition over the package inductive. A user
    `sum_list` fold and `sum_list(append(xs, ys)) = add(sum_list(xs),
    sum_list(ys))` by induction both check (`docs/hol/examples/
    list_fold_sum.ctea`; tests `defrec_*_package_list_*` in `lib.rs`), so a
    package-level fold/sum export is no longer needed for the handshake
    vertical. Original entry: no user recursion over the imported generic
    `List`, and no fold/sum in any package. `defrec sum_list (l :
    C.List Nat) : Nat` is rejected (recursion is limited to `Nat` and
    locally declared `data` types), so degree sums and edge counts — the
    roadmap's own handshake vertical — cannot be expressed against the
    counting library. The workaround (a private monomorphic list) forfeits
    every package theorem. Either `defrec` over package datatypes or a
    checked fold/sum surface in the List package unblocks the vertical.

42. **Resolved 2026-09-04: package identity and theorem-search aliases.**
    Independent aliases of the same logical package now share the first
    loaded surface representative, selected by stable package declaration
    identity. List, finite, and cardinality aliases compose with the counting
    source module, including theorem application, rewriting, induction,
    `defrec`, and map receipts. Local binders retain their meaning: alias
    resolution does not capture a package reference into a local variable.
    `docs/hol/examples/package_aliases.ctea` is checked by native and Wasm
    interface regressions; adversarial tests keep unrelated datatypes and
    element types distinct. Original failure: `C.List Nat` and `F.List Nat`
    from the same package did not unify. Browser search now includes logical
    package exports, groups aliases by checked receipt identity, and retains
    lookup/insertion by each alias. The real-editor browser harness verifies
    this path. Terminal and line-mode search also include package exports and
    group by receipt identity, retaining each alias as a usable search query.
    Search catalogs remain separate from the accepted source-declaration list.

43. **Resolved 2026-09-04: import cascades and portable standard imports.**
    The prelude/counting collision now produces one diagnostic at the caller's
    import line, with an explicit source-module alias suggestion. Their two
    List types remain distinct; `docs/hol/examples/prelude_counting.ctea`
    checks their coexistence under an alias in both import orders. Imports
    publish atomically: a failed source module rolls back its declarations,
    newly loaded dependencies, and HOL receipts. The checker stops at a failed
    import instead of emitting dependent unknown-name errors. Earlier root
    declarations and successful imports remain available. Native and virtual
    import tests cover rollback, retry, kernel-only rejection, and preservation
    of the legacy driver's logical-package retry flag; Wasm-interface tests
    cover checking, stepping, and explanations. Exact `std/...` imports now
    fall back to the shipped library outside a checkout; `builtin:std/...`
    selects it explicitly. Subprocess tests verify external homework and
    manifests, filesystem precedence, dependency isolation, and rejection of
    substituted or unauthorized libraries.

44. **Resolved 2026-09-04: native grading-surface gaps.** Native manifests
    now accept `allowed_theorems` with exact public logical-package identities,
    such as `std/hol/cardinality@1::map_length`. Grants preserve the client's
    own statement/proof limits and transitive trust restrictions. Canonical
    source-library export identities are supported too. The checked
    `docs/hol/pilot/pigeonhole_client.ctea` and accompanying manifest demonstrate
    the supplied-library workflow at fol+induction, with the full dependency
    receipt preserved. The chapter-15 solutions themselves contain higher-order
    helper statements and still require the HOL profile. Structured outcomes are resolved 2026-09-04:
    CLI and Wasm JSON now provide `theorem_outcomes[]` for every parsed theorem
    or axiom occurrence, including failures, skipped work, and import rollback.
    The accepted-only `theorems[]` remains available for compatibility.
    Excessive parsing now returns JSON diagnostics under explicit resource
    limits, including the former thousand- and fifty-thousand-parenthesis
    failure cases. Browser worker isolation and external batch execution
    limits are implemented; complete in-process budgets remain readiness work.

45. **Resolved 2026-09-03 (diagnostics misdirection batch).** Bare `cases h`
    and `induction n` now explain the `with` arm skeleton; an unregistered
    package version names the registered packages; tactic, hypothesis and
    theorem typos get a "did you mean" (Damerau-Levenshtein, bounded by
    name length) and bare names of aliased imports point at the alias; a
    predicate passed as a function argument is named as a predicate with
    the `Prop`-versus-data explanation; the `refl` hint on package-function
    goals names the package's computation theorems instead of `simp`;
    `defrec` arms accept `| node(l, v, r) recl recr =>` and a `:=` on the
    header is explained; an empty arm body followed by an unindented line
    is reported at the arm as an indentation mistake; and editor search
    ANDs whitespace-separated words. Regression tests:
    `diagnostics_batch_tests` in `lib.rs` and
    `search_ands_whitespace_separated_words` in the CLI. Original entry:
    Bare
    `cases h` reports ``unknown tactic `cases h` `` while the help lists
    `cases` as valid; `import std/hol/list@2` falls through to a raw
    filesystem error instead of naming the three registered packages; no
    "did you mean" exists anywhere (typo'd theorem references are called
    unknown *hypotheses* and steered toward projections); a declared
    predicate passed as a function argument is called "unknown function";
    `defrec` arms reject the term-syntax spelling `node(l, v, r)` with an
    irrelevant note about declaration order (arms want space-separated
    binders); a misindented case-arm body surfaces as ``expected `right`
    case arm`` at the student's own tactic; aliased imports give no
    short-name hint (`add_comm` after `import std/nat.ctea as nat` should
    suggest `nat.add_comm`); multi-word theorem search (`search add
    succ`) matches nothing where `add_succ` finds six theorems.
